## 1. 概要

### 1.1 VaporView とは

VaporView は VCD (Value Change Dump) / FST / GHW（GHDL ネイティブ形式）の波形を VSCode 上で直接表示できる拡張機能。

| 項目 | 内容 |
|------|------|
| 開発者 | Lramseyer（個人開発、活発） |
| ライセンス | AGPL-3.0（OSS） |
| 最新 | v1.5.2（2026年4月リリース、631 commits） |
| 必要要件 | VSCode 1.102.0 以上 |
| 対応OS | Linux/macOS/Windows + Remote SSH |
| 対応形式 | VCD / FST / GHW（FSDB は外部ライブラリ追加で対応） |

### 1.2 採用経緯（WaveTrace からの乗り換え）

当初は WaveTrace を採用していたが、以下の理由で VaporView に切り替えた:

1. **WaveTrace は信号値の文字が信号行高に対して上部見切れ**、行高調整の設定が公式に存在しない
2. **WaveTrace 公式サイト（wavetrace.io）は 2026年5月時点で 404**、メンテナンス停滞の兆候
3. **VaporView は OSS / 活発に更新 / 機能豊富**：行高調整・多彩な数値フォーマット・主副マーカー・FST/GHW 対応

Phase 5 MMU 規模で VCD が肥大化した場合は **FST 形式（バイナリ圧縮）** に切り替え可能、長期的にも VaporView が有利。

## 3. 基本操作

### 3.1 .vcd ファイルを開く

VSCode のエクスプローラから `.vcd` ファイルをクリック → VaporView が起動して波形が開く。

ヘッダの「**Auto Reload**」チェックボックスを ON にしておくと、再シミュレーション（`make sim`）で `.vcd` が更新されたときに波形が自動再読込される。**Phase 1 のデバッグサイクルでは ON 固定推奨**。

### 3.2 信号追加・削除

#### 3.2.1 NETLIST ペイン

ビュー左側に NETLIST ペインが表示される。`.vcd` 内のスコープ階層がツリー表示される。

00_counter テストベンチの例:

```
led_tb
├── counter[23:0]   (uut スコープ内)
├── sys_clk
├── sys_rst_n
├── led[5:0]        (uut スコープ内)
└── uut
    ├── counter[23:0]
    ├── sys_clk
    ├── sys_rst_n
    └── led[5:0]
```

#### 3.2.2 信号の追加

ツリー上で観察したい信号をクリック → 中央の波形ペインに追加される。

複数選択（`Ctrl + クリック` / `Shift + クリック`）で一括追加可能。

#### 3.2.3 信号の削除

波形ペインの信号を選択 → 右クリック → **Remove**。

複数の信号をまとめて消す場合は範囲選択。

### 3.3 行高（Row Height）の調整 — 文字見切れ対策

信号値の文字が信号行の高さに対して見切れる場合、信号を **右クリック → 行高選択**。

プリセットの中から選択（Compact / Standard / Tall 等）。

アナログ波形（FST 等で実数値表示の場合）は `Alt + +` / `Alt + -` で垂直ズーム可能。

> **TIPS**: 多bit の信号（counter[23:0] 等）は数値表示が長いため Standard 以上の行高が読みやすい。`sys_clk` のような単bit はCompactでもOK。

### 3.4 数値フォーマット切替

信号を右クリック → **Format Values** で数値表示形式を切り替え:

| 形式 | 用途 |
|------|------|
| Binary | ビット単位の挙動確認、命令フィールド分解 |
| **Hex** | デフォルト推奨、レジスタ値・PC 値表示 |
| Octal | 8進が必要な場面（稀） |
| Decimal | カウンタ・サイクル数の直感的把握 |
| Fixed Point | Q 数値表現 |
| Float (IEEE 754) | 浮動小数点演算結果（M 拡張以降） |
| ASCII | UART 等の文字列ストリーム |
| Epoch | UNIX time 表示（用途特殊） |
| Enum | 状態機械・命令デコード結果（カスタム定義） |

#### Phase 1 RV32I のデバッグ標準セットアップ

| 信号種類 | 推奨形式 |
|---------|---------|
| PC, 命令, ALU 出力, レジスタ値 | Hex |
| Counter, サイクル数, タイマ値 | Decimal |
| 命令フィールド分解（opcode/funct3/funct7） | Binary |
| 状態機械（FSM 状態） | Enum |

## 4. 波形ナビゲーション

### 4.1 ズーム

| 操作 | 手段 |
|------|------|
| ズームイン/アウト | **`Ctrl + マウスホイール`** |
| 範囲ズーム | ドラッグで時間範囲を選択 |
| ピンチズーム | タッチパッド対応 |
| 全体表示 | コマンドパレット → VaporView Zoom Fit |

### 4.2 パン（横スクロール）

マウスホイール（ズームと自動判定切替）。

### 4.3 マーカー（時刻計測）

| 操作 | 手段 |
|------|------|
| 主マーカー | クリック |
| 副マーカー | **`Alt + クリック`** または中ボタン |

主・副マーカー間の **時刻差** を計測可能。

クロック周期測定（27MHz = 約37ns）、リセット解除タイミング、クリティカルパス遅延計測などに使用。

#### 実例: 27MHz クロック周期計測

1. `sys_clk` のある立ち上がりエッジでクリック → 主マーカー
2. **隣の**立ち上がりエッジで `Alt + クリック` → 副マーカー
3. 時刻差が **37000ps = 37ns** になることを確認
4. 27MHz = 1 / 37ns ≒ 27.0MHz、setup_guide 通り

### 4.4 矢印キーでエッジ単位ジャンプ（神機能）

信号を選択した状態で:

| キー | 動作 |
|------|------|
| `→` | 次の信号エッジ（立ち上がり/立ち下がり）にジャンプ |
| `←` | 前のエッジに戻る |
| `↑` | 上の信号に選択移動 |
| `↓` | 下の信号に選択移動 |

クロック信号上で `→` を押すと、1サイクルずつステップ実行する感覚で観察可能。
Phase 1 で「PC が1命令ずつ進む様子を追う」ときの主力操作。

### 4.5 ステータスバー時刻表示

VSCode 下部ステータスバーに、現在のマーカー位置の時刻が表示される（例: `Time: 37 ns`）。

## 5. Phase 1 RV32I 波形デバッグ実践パターン

### 5.1 PC（プログラムカウンタ）追跡

PC 信号を Hex 表示で追加。`→` キーでクロック立ち上がりごとにステップして、命令ごとに PC が +4 進むことを確認。

```
立ち上がり時刻       PC
#100,000ps          0x0000_0000
#137,000ps          0x0000_0004
#174,000ps          0x0000_0008
...
```

ジャンプ命令時に PC が `+4` 以外の値に飛ぶ瞬間を波形で確認可能。BRANCH 命令の分岐先計算ミスは PC 飛び先の異常値で即座に発見できる。

### 5.2 レジスタファイル（x0 〜 x31）の値追跡

レジスタファイルが信号として exposed されている場合（テストベンチで `$dumpvars` 対象に含めれば波形に出る）、Hex 表示で観察。

`addi x1, x0, 5` 実行直後に `x1 = 0x0000_0005` になることを波形で確認。**WB ステージの完了サイクルで値が確定する**ため、書き込み遅延の理解にも使える。

### 5.3 命令デコード結果のフィールド分解

命令信号を Binary 表示にして、RISC-V フォーマット（R/I/S/B/U/J）のフィールド分解を目視確認:

```
RV32I R-type:
opcode    rd      funct3  rs1     rs2     funct7
[6:0]    [11:7]  [14:12] [19:15] [24:20] [31:25]
```

Enum 表示でカスタム定義（`OPCODE_LUI`, `OPCODE_OP`, `OPCODE_BRANCH` 等）を割り当てれば、命令名で表示可能 → デコーダの実装ミスが命令名レベルで見つかる。

### 5.4 クロック単位ステップ実行

`sys_clk` を選択 → `→` キーで 1 サイクル進む。各サイクルで:

- PC の進行
- 命令フェッチ結果
- レジスタ更新
- メモリアクセス

を順次確認。printf デバッグの神視点版で、CPU 内部状態を完全に観測できる。

### 5.5 パイプライン動作の波形理解（Phase 1 後半）

5段パイプライン（IF/ID/EX/MEM/WB）の場合、各段の信号を縦に並べる:

```
時刻       T0    T1    T2    T3    T4    T5
IF.pc      0x00  0x04  0x08  0x0C  0x10  0x14
ID.instr         0x..  0x..  0x..  0x..  0x..
EX.alu_out             0x..  0x..  0x..  0x..
MEM.mem_data                 0x..  0x..  0x..
WB.rd_data                         0x..  0x..
```

ストール、フォワーディング、ハザード解消が波形で見える。命令同士の重複実行関係が一目で把握できる。

## 6. WaveDrom 形式コピー（Markdown 埋め込み）

選択範囲を **WaveDrom 形式の JSON** としてコピー可能（最大32イベント）。

設計書（`docs/03_phase1_design.md` 等）に波形図を埋め込む際に便利:

````markdown
```wavedrom
{
  "signal": [
    { "name": "clk",  "wave": "p..." },
    { "name": "data", "wave": "x.34", "data": ["A", "B"] }
  ]
}
```
````

VSCode の `WaveDrom Editor` 拡張や [wavedrom.com](https://wavedrom.com/) で可視化される。設計書に「期待される波形」を残しておくと、レビュー・将来の自分のためのドキュメントになる。

## 7. トラブルシューティング

### 7.1 .vcd を開いても VaporView が起動しない

- VaporView 拡張がインストールされていない、または Local 側のみで Remote 側に未インストール
- VSCode を Remote SSH 接続中に拡張パネルから「**Install in SSH: <ホスト>**」をクリック

### 7.2 信号が NETLIST ペインに表示されない

- VCD の `$dumpvars` で対象スコープが含まれていない可能性
- テストベンチで `$dumpvars(0, top_module)` （depth=0 = 全階層ダンプ）を指定すること

### 7.3 行高を調整しても文字見切れが解消しない

- VSCode フォントサイズが大きすぎる可能性、`Editor: Font Size`（`Ctrl+,`）を一時的に下げる
- それでも治らない場合は VaporView の issue として報告: https://github.com/Lramseyer/vaporview/issues

### 7.4 大規模 VCD でパフォーマンス低下

- 100MB 以上の VCD で動作が重くなる場合、テストベンチで `$dumpvars` の対象を絞る（top のみダンプ等）
- または **FST 形式（バイナリ圧縮）** への切り替え:
  - iverilog: `vcd2fst dump.vcd dump.fst` で変換
  - Verilator: `+trace-fst` オプションで直接出力

### 7.5 Auto Reload が効かない

- ファイル監視のタイムアウト設定の問題
- VSCode ウィンドウ再読み込み（`Ctrl+Shift+P` → "Reload Window"）
